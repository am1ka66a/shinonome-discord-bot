# 管理員查帳

僅主機白名單的兩位管理者可使用，所有查詢均以私人訊息回覆。伺服器管理權限不能取代主機白名單。

- `/admin_audit account member:玩家`：查看餘額、等級、戰績、黑名單狀態及完整總帳。也可填 `user_id`，不會替不存在的玩家建立帳戶。
- `/admin_audit resets`：最近 50 筆重置操作，包含操作者、操作編號、影響帳戶數及總調整額。可指定玩家篩選。
- `/admin_audit resets operation_id:編號`：查看該次重置前的快照、設定金額及目前餘額；最多顯示 100 位，可指定玩家縮小範圍。目前餘額可能已因後續遊戲改變。
- `/admin_audit pending`：查詢待結算與已逾時的遊戲；另顯示輪盤待結算數及所有對局數；待結算保留已保存結果自動重試，其他輪盤可能仍正常進行中。此指令不會退款、重付或改變遊戲狀態。
- `/admin_audit reconcile`：比對每個帳戶的餘額與總帳（`casino_logs`）流水合計，列出差額最大的帳戶與總帳中不存在的帳戶。差額＝餘額−總帳合計−基準。唯讀。
- `/admin_audit reconcile set_baseline:True`：總帳建立前的歷史會造成差額，確認後把目前每個帳戶的差額記為基準；之後只顯示基準之後新出現的差額。需在 60 秒內按確認，只寫入基準表，不改變任何餘額或流水；再次設定會取代舊基準。
- `/admin_audit health`：私人查看本次程序運行時間、Discord 延遲、資料庫初始化、最近執行權檢查時間及各背景任務的運行／等待恢復狀態。不連線資料庫做查詢，初始化未完成時仍可使用。

帳戶面板每頁 10 筆，以初次查詢的最新總帳 ID 作為上界，之後新進的流水不會擠動頁面。餘額、戰績及上界固定於初次查詢；重新執行指令可更新。面板 3 分鐘後停用，只有原查詢管理者可翻頁，翻頁失敗會保留原頁。

總帳來自不受短期清理影響的 `casino_logs`。**總帳 ID 與短期流水 ID 是不同編號**。既有 `/admin_revert_tx` 使用的是短期流水 ID；總帳頁面同時標示兩者，無短期編號的歷史總帳不能直接拿總帳編號沖正。

資料庫版本 3 只新增查帳索引，不改變帳戶、餘額或歷史紀錄。查詢皆有限制筆數，總帳以游標翻頁，不做全表傳回。重置快照從版本 2 上線後的重置操作開始記錄，無法補回之前未保存的快照。

資料庫版本 4 新增 `users.startup_granted`；版本 5 新增 `bot_reconcile_baseline`、`bot_reconcile_meta`，皆不改變既有餘額或流水。
